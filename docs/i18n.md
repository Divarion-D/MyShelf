# Localization (i18n)

The interface can be shown in multiple languages. All UI strings are stored in translation files under `assets/i18n/`, and [`assets/js/main.js`](../assets/js/main.js) loads the right one at runtime and substitutes it into the page.

Two languages ship by default: **Russian (`ru`, default)** and **English (`en`)**.

## Files

Each language is a **separate file**; a small config lists the available languages.

```text
assets/i18n/
├── config.json   # available languages + default
├── ru.json       # Russian strings
└── en.json       # English strings
```

### `config.json`

```json
{
  "default": "ru",
  "languages": [
    { "code": "ru", "label": "Русский" },
    { "code": "en", "label": "English" }
  ]
}
```

- `default` — the language used when nothing is selected, and the fallback for any missing key.
- `languages` — the list shown in the switcher. `code` must match the `<code>.json` filename; `label` is the human-readable name.

### `<code>.json`

A flat map of **key → translated string**. Both language files must contain the same keys.

```json
{
  "nav.home": "Главная",
  "filter.apply": "Применить фильтр",
  "category.heading": "{category}: {view}"
}
```

## How it works

On page load, `main.js`:

1. Fetches `config.json` to learn the languages and default.
2. Resolves the active language (see below) and fetches `<code>.json`, plus the default language as a fallback dictionary.
3. Sets `<html lang>` to the active code.
4. Substitutes translations in two ways:
   - **Static markup** — elements carrying a `data-i18n*` attribute (see below).
   - **Dynamic strings** — everything rendered by JS (cards, menus, headings, modal) goes through the `t()` helper.

### Language resolution order

1. `?lang=<code>` query parameter (if valid) — also saved as the preference.
2. `myshelf_lang` in `localStorage`.
3. `default` from `config.json`.

### Switching

A switcher (`.language-switch`) is rendered into the header on both pages. Selecting a language saves it to `localStorage` and reloads the page so the whole UI re-renders. Everything else (data, theme) is unaffected, and cached JSON makes the reload cheap.

## Placeholders

Strings can contain `{name}` placeholders, filled in by `t(key, params)`:

```json
{ "category.heading": "{category}: {view}" }
```

```js
t('category.heading', { category: 'Anime', view: 'Watched' }); // "Anime: Watched"
```

## Marking static HTML for translation

Add one of these attributes to an element; the value is the translation key:

| Attribute               | Effect |
|-------------------------|--------|
| `data-i18n`             | Sets the element's `textContent`. |
| `data-i18n-placeholder` | Sets the `placeholder` attribute (inputs). |
| `data-i18n-content`     | Sets the `content` attribute (meta tags). |
| `data-i18n-alt`         | Sets the `alt` attribute (images). |

```html
<span data-i18n="home.stat.total">Total in category</span>
<input data-i18n-placeholder="filter.searchPlaceholder">
```

Keep the element's text as the default-language value — it shows before JS runs and is what you edit from.

## Adding a language

1. Copy `assets/i18n/ru.json` to `assets/i18n/<code>.json` and translate every value (keep the keys).
2. Add an entry to `config.json`'s `languages` array with the matching `code` and a `label`.

That's it — the switcher and loader pick it up automatically.

## Adding or changing a string

1. Add the key to **every** `<code>.json` file.
2. In HTML, tag the element with `data-i18n` (or a variant) and the key.
3. In JS, output it via `t('your.key')` instead of a literal.

Category and media-type labels are translations too — `category.<key>` and `mediaType.<key>` — so translating those files is all that is needed to relabel them; see [data-schema.md](data-schema.md).
